#38 - Refactor Homepage Hero to a Full-Bleed Responsive Component

What & Why

The homepage hero is currently constrained inside a max-width container,
preventing it from stretching edge-to-edge across the viewport.
Additionally, the left-panel hero images have their background colors
baked into the exported graphics.

This task should refactor the hero into a reusable, responsive component
by:

-   replacing the existing hero graphics with the new transparent PNG
    assets,
-   moving all background colors into CSS,
-   allowing both the left and right panels to expand independently
    across the full browser width,
-   preserving the existing visual design while making the layout fully
    responsive.

Unlike the rest of the site, the homepage hero is intentionally a
full-bleed component and should not inherit the site’s shared max-width
layout system.

Done looks like

-   The hero spans the full viewport width at every screen size with no
    whitespace outside either panel.
-   The split between the left and right panels remains centered in the
    viewport regardless of browser width.
-   Both panels expand equally as the viewport grows rather than
    anchoring from one side.
-   The left panel displays a CSS background color with the transparent
    arched PNG centered inside.
-   The image scales using object-fit: contain and never stretches or
    crops.
-   The right blue panel (#002fa7) remains visually unchanged.
-   Typography, spacing, navigation, copy, and animations are preserved.
-   The hero uses: min-height: clamp(700px, 85vh, 980px); instead of a
    fixed height.
-   The homepage hero remains full-bleed while the rest of the site
    continues using the shared responsive container system.

Out of scope

-   Typography
-   Copy
-   Navigation
-   Header
-   Other homepage sections
-   Project pages
-   Mobile redesign (Task #10)

Implementation

1. Replace hero assets

Replace the existing hero image assets with the newly uploaded
transparent PNGs and update all image references accordingly.

These new PNGs contain only the arched photograph on a transparent
background.

The background color should now come entirely from CSS.

2. Associate each image with its background color

Rather than mapping colors by image position, associate each hero image
with its corresponding background color directly in the hero data
structure.

Example:

{ image: homeHero1, background: “#E2CFEA” }

Available colors:

-   #FFB41F
-   #F24333
-   #5E0035
-   #71D4F8
-   #E2CFEA

3. Remove the hero max-width constraint

The homepage hero should not inherit from ContainerLayout or any other
shared max-width wrapper.

Instead:

-   the hero background panels should extend edge-to-edge across the
    viewport,
-   while the internal composition remains visually balanced.

4. Refactor the left panel

The left panel should:

-   use the assigned CSS background color,
-   center the transparent PNG both vertically and horizontally,
-   use Flexbox or CSS Grid for centering,
-   use object-fit: contain,
-   limit the image to approximately: max-width: 80%; max-height: 80%;

The image should never distort or crop.

The background should expand independently of the image.

5. Preserve the right panel

Keep the existing:

-   bg-[#002fa7]
-   typography
-   copy
-   spacing
-   max-w-[580px]

No visual redesign is needed.

6. Hero sizing

Replace the existing fixed viewport height with:

min-height: clamp(700px, 85vh, 980px);

Maintain the existing two-column layout on medium screens and larger.

7. Final verification

Verify at:

-   320px
-   768px
-   1024px
-   1440px
-   1920px

Confirm:

-   no horizontal scrolling,
-   both panels expand evenly,
-   the hero remains centered,
-   the split stays centered,
-   images scale naturally,
-   the visual design matches the current homepage.

This refactor should preserve the current design while rebuilding the
hero as a reusable, responsive full-bleed component that is independent
of the site’s shared content container.
