I want to add a lightweight custom CMS/admin section to my existing portfolio website so I can manage case-study content myself without having to prompt Replit every time.

IMPORTANT: Do not redesign the public website or change its existing visual design, typography, layout, navigation, animations, responsive behavior, or case-study styling unless required to support the CMS. The goal is to make the existing site content-driven and editable, not to rebuild the site.

My current portfolio is:
https://www.kristenbend.com/

Before making changes, please inspect the existing codebase and understand:

* how the homepage projects are currently stored/rendered
* how the reusable case-study template works
* how images are currently referenced/stored
* what database/storage/authentication infrastructure already exists
* how the Building Bridges case study is currently structured
* whether there is already any admin/content architecture that can be extended

Then propose the simplest, most reliable architecture for a small custom portfolio CMS using the existing project infrastructure wherever possible. Do not introduce unnecessary services, subscriptions, or complexity.

GOAL

I want a private admin area, such as:

/admin

where I can manage my portfolio projects without needing to ask Replit to make routine content or layout changes.

The CMS should control the content and structure of the case studies while the existing public-facing design remains the presentation layer.

ADMIN / AUTHENTICATION

Create a secure admin login for me.

The admin area should:

* require authentication
* not be publicly accessible without logging in
* keep credentials/secrets out of the frontend code
* use the simplest secure authentication approach appropriate for the existing app
* include logout
* prevent unauthenticated users from accessing admin routes or APIs

I am the only person who needs to manage the site, so this does NOT need multi-user roles or permissions.

PROJECT MANAGEMENT

Create an admin Projects area where I can:

* view all case studies
* create a new case study
* edit an existing case study
* duplicate a case study if useful
* save a project as Draft or Published
* delete/archive a project with an appropriate confirmation
* control whether a project appears on the homepage
* reorder projects on the homepage using drag-and-drop
* save the homepage project order

The homepage order should come from the CMS rather than being hard-coded.

For example, I should be able to drag:

Building Bridges
Journey to Net Zero
COP28
Expo 2020

into a different order in the admin area and have the public homepage reflect that order after saving/publishing.

CASE STUDY CONTENT EDITOR

I want to be able to edit the text of each case study without touching code.

The editor should support the content that the existing reusable case-study template already uses, including whatever fields are currently appropriate for projects such as Building Bridges.

At minimum, structure the content so I can edit:

* project title
* subtitle/short description
* client
* year
* role
* project overview/introduction
* section headings
* body copy
* any other recurring text fields already present in the current case-study template

Do not invent unnecessary fields if the current site does not need them.

For longer case studies, I want to be able to control the sequence of content rather than being forced into one giant text field.

Ideally, the case study should be composed of reusable content blocks/sections, for example:

* text section
* image
* image gallery
* image pair/grid
* video/media if the current site already supports it

The exact block types should be based on the existing case-study design. Keep the system flexible enough that I can rearrange sections without asking Replit to edit code.

IMAGE / GALLERY MANAGEMENT

This is one of the most important parts.

I want to be able to manage the images in each case study myself.

For every image/media item, I should be able to:

* upload an image
* select an existing uploaded image where appropriate
* remove an image from the case study without necessarily deleting the underlying file
* reorder images using drag-and-drop
* move an image to a different position in the case study
* add/edit a caption
* choose whether the caption is displayed
* choose the image’s layout/size

I specifically want control over which images are wide and which are smaller.

The layout controls should use the existing site’s visual system rather than arbitrary pixel widths. For example, if the current design supports variations such as:

* full-width/wide
* large
* half-width
* two-up
* three-up
* smaller/contained

then expose those as simple choices in the admin UI.

Please inspect the current Building Bridges case study and use its actual visual patterns as the basis for these layout options.

I want to be able to visually understand the order and layout of the media in the admin editor.

A drag-and-drop interface would be ideal.

For example:

IMAGE
[thumbnail]

Layout: [Full Width ▼]
Caption: [……………………]
Show caption: [✓]

[drag handle] Move

Then the next content block/image, etc.

IMPORTANT: Do not expose raw CSS classes, pixel values, HTML, or code to me as the content editor. I should be able to make these decisions through simple UI controls.

IMAGE UPLOADS / STORAGE

Please inspect how images are currently handled.

Use the existing image/storage infrastructure if it is appropriate. If a proper persistent storage solution is needed, choose the simplest reliable option compatible with the current app.

Do not store important uploaded images only in temporary/local filesystem storage if that would cause them to disappear on redeploy.

The CMS should preserve image references when projects are edited or reordered.

If possible, maintain a reusable media library so that an uploaded image can be reused in another project without uploading it again.

PUBLIC CASE STUDY RENDERING

The existing public case-study template should become data-driven.

The public page should continue to look essentially exactly as it does now.

The CMS should provide the content to the existing reusable template.

This means:

* same design system
* same typography
* same spacing
* same image treatment
* same responsive behavior
* same navigation
* same animations/interactions
* same overall visual hierarchy

The difference is that the content and sequence now come from the CMS.

PREVIEW / PUBLISHING

I would like a Draft/Published workflow.

Ideally:

* Save Draft
* Preview
* Publish

Draft edits should not accidentally change the public site.

If implementing a full preview system would add disproportionate complexity, start with a simple reliable Draft/Published system and explain the tradeoff.

ADMIN UX

The admin interface does not need to look like a sophisticated enterprise CMS.

It should be:

* clean
* simple
* intuitive
* easy for a non-developer to use
* visually clear
* optimized for managing a small portfolio

I especially want drag-and-drop controls for:

* homepage project ordering
* case-study content block ordering
* gallery/image ordering

Please include clear Save/Publish feedback so I know when changes have actually been saved.

DATA MODEL

Please design the content model so that adding a new project in the future does NOT require a developer to create a new page.

Ideally the workflow should eventually be:

Admin → New Project → Add content/images → Arrange sections → Save/Preview → Publish

and the reusable public case-study template handles the rest.

Do NOT create a separate custom backend implementation for every project.
